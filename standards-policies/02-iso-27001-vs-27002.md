# 2. ISO/IEC 27001 vs ISO/IEC 27002

Short version: **27001 is the requirements standard you certify against; 27002 is the
guidance on how to implement the controls 27001 lists.**

## ISO/IEC 27001:2022

- Specifies the requirements for an information security management system (ISMS).
- Clauses 4–10 are the mandatory core: context, leadership, planning (including risk
  assessment 6.1.2 and risk treatment 6.1.3), support, operation, performance
  evaluation, improvement.
- Annex A lists 93 controls as one-line statements only — 8.12 is a single sentence.
- Controls are selected through risk treatment. Inclusions and exclusions are justified
  in the **Statement of Applicability** (6.1.3 d). You don't have to implement every
  Annex A control, but you must consider each one and justify leaving it out.
- Written with "shall", therefore auditable. This is the certifiable document.

## ISO/IEC 27002:2022

- A code of practice, not a set of requirements. Written with "should"; you cannot be
  certified against it.
- Same 93 controls, same numbering, but each gets: control statement, purpose,
  guidance, other information.
- Adds five **attributes** per control (clause 4.2) — control type, information security
  properties, cybersecurity concepts, operational capabilities, security domains — so
  controls can be re-sorted into custom views (Annex A of 27002) and aligned with other
  frameworks.
- Annex B gives the correspondence with ISO/IEC 27002:2013 and marks which controls are new.

## In practice

27001 says you need a risk-based ISMS and must address 8.12 or justify excluding it.
27002 says what a reasonable 8.12 implementation looks like. Auditors certify against
27001 but frequently use 27002 as the reference for whether a control is adequate.

## Citation rule used in this repo

- The **requirement** exists → cite ISO/IEC 27001:2022, Annex A, 8.12.
- What the control **involves** → cite ISO/IEC 27002:2022, 8.12.
