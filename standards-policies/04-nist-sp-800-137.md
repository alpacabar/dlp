# 4. NIST SP 800-137 (2011), Appendix D.1.8 — information management

SP 800-137 is about information security continuous monitoring (ISCM). DLP appears in
Appendix D as one supporting technology area. It is guidance: voluntary unless a contract
or regulation (e.g. for some US federal systems) makes it binding.

## The taxonomy

```
data loss  (umbrella: exposure of proprietary, sensitive or classified information)
├── data theft    — intentional: espionage, employee disgruntlement
└── data leakage  — inadvertent: lost/stolen laptop, files in an internet storage app,
                    files copied to USB to take home
```

Two points worth noting:

1. **"Leakage" here is the accidental subset only.** ISO uses the same word for the whole
   problem. See [06-iso-vs-nist.md](06-iso-vs-nist.md).
2. **The examples blur the line.** Saving files to a USB drive or a personal cloud app is
   a deliberate *action* classified as inadvertent *exposure*. The distinction therefore
   rests on intent to expose, not intent to act — relevant to insider-threat modelling.

## The DLP strategy

An effective DLP strategy includes:

- data inventory and classification;
- data metric collection;
- policy development for data creation, use, storage, transmission and disposal;
- tools to monitor data **at rest, in use and in transit**.

Tooling is split between general-purpose security tools (network analysis software,
application firewalls, IDS/IPS) and purpose-built DLP software (port and endpoint control,
disk and file encryption, database transaction monitoring), deployed as network monitors
or as agents on desktops, laptops and servers. Built-in responses: email alerting,
logging, blocking transmissions.

## Control mapping — and the Rev. 3 problem

SP 800-137 lists the SP 800-53 controls DLP helps implement, assess and monitor. Those
are **Revision 3** identifiers. Current mapping:

| As printed in SP 800-137 | Status in SP 800-53 Rev. 5 |
|---|---|
| AC-4, Information Flow Enforcement | unchanged |
| AC-17, Remote Access | unchanged |
| CA-3, Information System Connections | renamed **Information Exchange** |
| CA-7, Continuous Monitoring | unchanged |
| CM-7, Least Functionality | unchanged |
| SC-9, Transmission Confidentiality | **withdrawn** in Rev. 4, folded into SC-8 (Transmission Confidentiality and Integrity) |
| SI-12, Information Output Handling and Retention | renamed **Information Management and Retention** |

If you cite the mapping, cite SP 800-137 for the idea and SP 800-53 Rev. 5 for the
current control names, rather than repeating the 2011 list unchanged.

## Citation note

Monev (2023) paraphrases this appendix as saying NIST calls intentional theft "data loss".
It does not: NIST calls intentional exposure "data theft" and uses "data loss" as the
umbrella. Cite the NIST text directly. See [07-monev-2023.md](07-monev-2023.md).
